# 架构

ShinApple 使用 SwiftUI 构建界面，局部使用 AppKit 管理窗口和歌词文本布局。官方「音乐」App 负责实际音频播放，应用通过公开脚本读状态和控制播放；本地歌词资料与官方音乐账号独立。

## 模块

| 模块 | 职责 |
|---|---|
| `App/` | 界面、窗口、界面状态及服务接线 |
| `ShinAppleKit` | 领域模型、播放和存储协议、LRC 解析、Mock |
| `ShinLyricsEngine` | 纯时间轴查询、歌词分组和偏移换算 |
| `ShinAppleData` | GRDB/SQLite 存储、事务、迁移、备份校验与恢复 |
| `ShinAppServices` | 导入、关联、编辑、播放与歌词协调、导出和备份工作流 |
| `ShinMusicScript` | 唯一 Music Apple Events 适配层，包含资料库、播放选项与封面读取 |
| `ShinLyricsProvider` | 唯一 HTTP 获取层，包含网易云候选查询、歌词文本获取、匹配和双语 LRC 合成 |

界面和服务通过注入协议调用播放、存储与歌词获取能力。领域模型和歌词引擎不依赖 SwiftUI、AppKit、播放系统、数据库或网络；网络层不直接写数据库，获取结果复用歌词导入与确认流程。

## 播放与歌词同步

Music 脚本快照是播放状态和位置的权威来源，所有内部时间使用整数毫秒，未知位置用 nil。展示层可从最近有效样本按单调时钟短时插值，默认外推上限 1 秒；新样本立即校正，暂停、切歌、停滞和陈旧样本停止推进。

播放请求入队时登记优先权，AppleScript 仍经进程内同一脚本门串行执行。实际等待执行的播放脚本优先于采样，采样可在长列表建立的批次之间及播放确认等待期间继续；资料库和列表封面脚本在每段脚本边界让播放先行。采样与控制统一先进入脚本门，再取播放执行锁；取消、dispose 和命令完成均释放排队优先权，专用退出清理仍可执行。已开始的单个 Apple Event 无法抢占。

当前曲目封面使用专属 Scripting Bridge 实例与独立锁，不持有播放执行锁；单次事件沿用统一超时，读取前后的 persistent ID 必须一致。切歌或取消后不再发起尚未开始的旧封面读取，迟到结果仍经曲目身份核验。封面暂不可用时，每次曲目变更或可见请求最多补试两次；资料库封面按真实来源定位，缺失及无法解码结果只短暂缓存，用户刷新或切换来源也可重新尝试，不随播放进度无限请求。

随机播放先核对请求成员与原用户歌单或资料库的完整成员，数量与成员均一致时，通过公开 `play` 直接启动该来源。搜索、艺人分组等子集使用应用管理歌单；已有同成员管理歌单时，重新验证预期名称、所有权标记和完整成员后复用，避免重复创建与逐曲复制。

点选指定歌曲时，将完整可见列表按所选曲旋转为「所选曲至末尾，再接开头至所选曲之前」，数量与成员不变，使用公开 `play targetPlaylist without once` 整单起播，避免单曲引用使 Music 切到资料库或在一曲后停止。所选曲是原来源首曲且完整顺序一致时使用原来源；其余情况优先复用旋转顺序一致、名称及所有权标记仍有效的自有管理歌单，无可用上下文才新建。管理歌单通过公开 `make user playlist` 和 `duplicate` 创建，只复制已有曲目引用，不修改原歌单或音频。复制时寻找连续区间，在同次脚本中核对该 numeric range 的全部ID及顺序后批量复制；索引不适用时按 persistent ID 逐项复制。每批最多执行24次复制操作，连续区间算一次，读回完整的已追加前缀后保存进度，批次之间检查取消。空歌单先检查曲目数量，不读取空列ID；已登记的非空管理歌单被用户清空时不再复用，也不删除用户改动。整个列表核对完成后才允许起播。

普通和随机启动都在 `play` 前读取目标歌单身份，`play` 后仅返回已保存的身份。普通点播先保存并暂关随机，再验证实际首曲；起播前不适用，或起播与确认失败、取消时恢复已知的原随机偏好，不修改 `fixed indexing`。起播后确认真实歌单身份、完整成员顺序、所选曲及正在播放，再恢复或设置随机状态并再次确认。确认及随机重设阶段短暂的对象缺失（`-1728`）在原有5秒期限内重验，`play` 自身的错误立即报告。随机启动只有在来源、完整成员、随机状态和 `playing` 均符合要求时才报告成功。

随机启动先尝试设置歌曲随机模式再播放；冷启动暂时无法预设随机状态时，先启动并在有界确认中核对来源及完整成员、设置随机，再播放同一歌单一次并再次确认。上一首、下一首和续播由 Music 在已确认的来源中执行。应用记录管理歌单所有权与成员，保留当前及最近一个可复用上下文；新播放确认后在短预算内最多处理两个更旧的自有清单，不遍历全部历史清单。回收重新核对非当前、准确名称、随机所有权标记及完整成员，失败不否定已成功的播放，留给退出清理。退出时只清理仍保持原状的管理歌单，用户修改后的歌单保留。已发出播放请求但尚未确认的歌单保留保护记录，未确认时不报告播放成功。

主页设置默认开启退出清理，偏好保存在本机 UserDefaults。正常退出通过 AppKit 的延迟退出流程，先同步取消本应用的订阅、播放与浏览任务、失效自动获取，并 dispose 播放控制器，使在途及排队中的旧命令失效；再在同一播放命令串行队列中只发送一次停止；Music 返回尚未停止时，在短预算内只读确认并响应取消。除 `stopped` 外，仅兼容 Music 停播后报告 `paused` 且当前歌曲、当前歌单均不存在的状态；普通暂停和活动播放仍拒绝清理。确认后才清理本机记录且所有权、名称、完整成员仍可验证的全部应用临时清单，包括刚停止播放的清单。用户修改过的清单保留，不凭名称删除无法核实归属的历史清单。完成或失败后放行退出；最多等待 10 秒，超时取消清理并立即放行，不等待尚未返回的 Apple Event。重复退出共用一轮清理；关闭设置及 Mock 仅停止本 App 任务，关闭窗口不触发退出流程。

侧栏的「喜爱歌曲」直接使用 Music 返回的用户播放列表 persistent ID，不从全库的 `favorited` 标记合成，也不按名称猜测或合并同名歌单。公开 `special kind` 中的 Library / Music 容器不作为用户歌单展示，其他及未知类型保留。点星在点击时的真实来源中定位曲目，以 Music 读回值更新标记；随后失效歌单成员缓存，并重读当前歌单，保留搜索、选择及滚动位置，避免喜爱或智能歌单继续显示旧成员。Music 未向公开脚本暴露的歌单无法额外推造。

当前播放列表通过公开 `current playlist` 识别资料库或用户歌单，再独立分页读取；不从浏览页面推测系统待播队列。切歌、关闭弹窗及重试会取消旧读取并检查请求顺序；来源未知时清空旧列表。

歌单浏览默认保持公开脚本批量返回的曲目顺序，不按歌单名称推测排序。Music 的 `fixed indexing` 可影响曲目索引与播放顺序的关系，但当前批量读序不保证等同官方界面显示顺序；`item.index` 也不能直接当作界面排序字段。用户可选择字段和方向，偏好仅按歌单 persistent ID 保存在本机 UserDefaults；同值稳定保留返回顺序，未知字段始终放末尾，过滤后沿用排序，并将完整显示顺序交给播放上下文。公开词典没有界面当前排序字段、升降序或收藏时间；添加时间采用 Music 返回的 `date added`，不保证与官方最近添加显示或收藏时间一致。

播放上下文错误以固定阶段和可选数字错误码跨层传递，不携带系统原始错误、曲目字段或脚本文本。建立、启动及随机确认失败与原来源不可用分别说明；建立失败后继续读取 Music 的实际当前列表，不把浏览页的筛选结果当成已经生效的待播列表。

文件 `sourceOffsetMs` 与用户 `userDelayMs` 独立保存，生效时间为 `line.startMs − sourceOffsetMs + userDelayMs`。正用户偏移表示延后；显示、点击跳转和导出共用换算。未打轴的行保留为静态文本，不冒充同步行。

用户偏移命令捕获当前绑定与文档 revision，并按调用顺序保存。存储事务重验目标，仅修改仍匹配的现有绑定偏移；换绑、解绑或人工编辑后拒绝旧命令，不创建绑定或回写关联字段。切歌后已提交的合法命令仍保存原歌词，错误提示按界面生命周期失效，不影响新歌曲。

关联刷新先等待已提交的偏移保存链，再重验请求是否仍有效并读取关联；快速切走后返回原歌曲也会读到已保存的偏移。刷新同时捕获偏移状态序号，同绑定、同文档版本的迟到查询不能覆盖更新的本地偏移。新绑定或文档版本使用其自身偏移。

等待展示只使用实际前奏和时间轴中的明确空白区间，不凭相邻歌词的间隔猜测句尾。较长等待显示三点，由权威播放位置依次填满；暂停冻结，未知位置不猜测进度，减少动态效果时使用静态样式。等待槽按文档及有效偏移预先排布，连续空白合并为紧凑槽，短等待收起；播放推进、暂停和 seek 只更新显示状态，不改变歌词行位置。

异步操作检查曲目或文档生命周期与请求顺序，防止旧结果覆盖新状态。采样、监听和动画可取消。手动歌词滚动、拖动和选词暂时挂起自动跟随，停止阅读后按本地设置的空闲时间恢复；设置变化按最后实际阅读活动重算，不当作新的阅读动作。导入、编辑与进度拖动各自保留明确的预览和提交边界。导入保存成功后自动关闭导入页，重查关联后核对曲目、文档、服务实例和导入代次，再立即恢复歌词跟随；暂停仍按已知权威位置定位，未知位置不猜测当前行。

完整与紧凑播放器的歌词动作合并到顶栏菜单，独立歌词侧栏保留自己的入口。菜单按面板状态启用偏移、译文、编辑和解除关联，解除确认固定曲目、生命周期、面板实例、文档和 revision；确认前与写事务中分别重验，切歌、换库、换绑或编辑后拒绝旧请求。解除最后一个歌曲关联时同时删除歌词和译文；共享歌词仅解除当前歌曲关联。

独立悬浮歌词窗由应用级控制器持有，复用同一播放快照、歌词面板和同步协调器；只投影当前曲目、生命周期与稳定行 ID 均匹配的已载入文档，不增建采样、索引或数据库读取。浮窗浏览与主歌词区的手动滚动、编辑挂起独立，主窗隐藏或关闭不停止同步；窗口位置按当前显示器可见区域校正，偏好只保存在本机。锁定使用系统整窗鼠标穿透并隐藏工具区，在鼠标悬停达到设置的等待时间后显示独立解锁按钮，避免正文拦截下方窗口操作；离开、解锁或关闭时清理悬停等待与按钮。底栏和应用菜单保留解锁入口；原生边角缩放区固定对侧锚点并约束最小尺寸和屏幕边界，中心区域保留歌词交互。悬浮窗不参与原生全屏。

未锁定时，悬浮窗正文与空白区域支持原生拖窗并显示抓取手形；工具按钮与边角缩放区优先命中，滚轮仍用于阅读长句。缩放方向使用适用系统版本的边角光标，不显示固定的右下角箭头。

悬浮歌词齿轮菜单复用现有在线获取与导入入口，恢复已知主窗口或通过主窗口组重开，再进入同一预览确认流程。悬浮歌词字体大小和字间距通过各自的本机偏好在浮窗与主设置间立即同步，只用于浮窗原文和译文的测量与换行；字体保留原文与译文的默认比例及系统辅助功能缩放，纵向行距和歌词组间距保留默认值，不更改主窗口的歌词排版。

## 身份与人工成果

歌词文档和行使用稳定 UUID，翻译绑定具体行及文本 revision，不能依赖数组位置。Music persistent ID 使用 `music-script:persistent:` 命名空间；旧备份的目录身份仍可读，不将两类标识混用，也不按歌名自动合并。

网络歌词包含来源、外部引用、匹配方式和获取时 revision 等注记。手动与自动获取统一排除标题明确标注伴奏、伴奏版或独立英文单词 Instrument / Instrumental（可接「版」）的候选，不根据歌手或专辑推断。其余候选保留歌名中的版本文本，总分相同时按未舍入的时长差从小到大排列，已知差值优先，仍相同则保留搜索返回顺序。自动获取只处理用户已配置播放列表的成员变化，有绑定的歌曲跳过；低置信匹配进入待确认列表。移出全部已选播放列表时，只有自动落位、获取后未编辑且没有人工翻译的文档可被自动清理。手动导入、用户确认和人工编辑内容均受保护。

当前歌词面板同时订阅数据层提供的数据库文件变更流。数据库与 WAL 的文件事件合并为有限通知，并监视目录以重新绑定被重建的文件；同连接、其他连接及同机其他实例的提交都能触发当前曲目关联重读，不依赖切歌或整轮自动获取完成。订阅随换库、退出和模型释放取消；刷新任务核对当前面板、曲目键和 epoch，旧库通知不进入新面板。普通播放位置采样仍只更新同步协调器，不读取数据库，也没有定时轮询。无本地歌词时提供只重读本地关联的手动入口，不联网获取或按歌名匹配。

设置中的「缓存资源管理」复用当前歌词库模型，按文档统计已关联与未关联资源，支持搜索、选择删除、清理未关联和删除全部。删除预览捕获文档 revision 和完整关联歌曲集合，确认后单事务重验全部目标，任何目标变化整批拒绝；原学习歌曲页的单项删除使用同一流程。每次删除确认有独立标识，多窗口交错不能将 A 的确认应用到 B。提交前暂停并等待在途自动获取，清除目标歌曲的获取待办；删除完成或失败后恢复此前的运行状态，避免旧结果写回或排队刷新再次抓取；换库使旧预览与迟到概览失效，删除期间禁止重复提交和切换保存位置。管理范围是当前库中的歌词、译文和歌曲关联，不清理导出备份、导入源文件、Music 音频或仅驻内存的封面。

## 边界

Music 脚本使用固定代码和受验证参数，不拼接用户文本为可执行代码。网易云获取访问集中定义的两个域名，匿名、限速，只查询歌曲信息与歌词文本；歌词端点并非官方公开 API，失败需明确呈现。

学习资料与获取结果存于本机，无遥测或上传。数据操作使用事务、revision 与增量迁移，细节见 [数据迁移](migration.md)。测试通过 Mock 和注入会话隔离 Music、网络与真实用户数据。
