# 数据迁移与恢复

本地歌词库由 `ShinAppleData` 使用 GRDB 7.7.0 访问 SQLite。数据库结构、歌词文档和备份文件有独立版本，不能将应用版本 0.1.0 当作数据格式版本。

## 当前版本

| 层级 | 当前版本 | 含义 |
|---|---|---|
| SQLite 结构 | v3 | 已应用的 GRDB 迁移记录 |
| `LyricDocument.schemaVersion` | 1 | 单篇歌词文档 JSON 模型 |
| `BackupFile.schemaVersion` | 2 | 完整备份顶层格式；导入兼容版本 1 和 2 |

数据库迁移依次为：

1. `v1.schema`：创建歌词文档、歌曲绑定和设置表。
2. `v2.trackKeyNamespace`：歌曲绑定同时支持旧目录身份和 Music persistent ID，两者只能择一。
3. `v3.documentSummary`：增加并回填文档摘要列，用于歌词库总览查询。

歌词文档 `payload` 保存完整数据，摘要列随写入同步维护；歌曲关联使用外键保护。GRDB 记录已执行迁移，后续只追加新迁移，不改写旧迁移。

## 打开与快照

应用启动时对已存在的库尽力导出 `lyrics.preopen.json`，随后正常打开数据库并应用待执行迁移。当前快照函数也会运行当前迁移器，因此快照可能包含本次迁移后的结构；它不是升级前原始数据库的保证副本。快照失败不阻止正常打开，也不删除原库。

每个迁移在事务中执行，失败回滚到上一已应用版本，并向界面报告错误。打开失败、数据损坏、迁移失败和备份拒绝均不得通过删库、清库或重建来自动修复。

升级前如需完整保护，应在退出应用后复制整个数据目录，或先在可正常运行的版本中导出 JSON 备份。数据库运行期间可能依赖 `lyrics.sqlite-wal` 与 `lyrics.sqlite-shm`，不要只复制主文件作为完整备份。

## JSON 备份

完整备份包含歌词、译文、时间、来源注记、歌曲关联、偏移和 revision。设置只导出明确白名单内的键，当前默认白名单为空；界面偏好、自定义目录和自动获取配置不随备份迁移。备份不含音频、账号或凭据。

导入先校验格式、版本、标识、时间和大小限制，再展示冲突预览，用户确认后单事务写入。默认上限为 2 MiB、10,000 篇文档、10,000 个绑定、10,000 行歌词总量和 JSON 深度 32；超限、非法类型、重复 ID 和未来版本在写入前整体拒绝。未知字段可被忽略，但需给出提示。

LRC 仅用于互操作，丢失译文、行 ID、来源等信息，不能替代 JSON 备份。

## 更改保存位置

应用运行时可以切换数据目录：新位置为空时使用一致性快照复制现有库；新位置已有歌词库时直接打开该库，不合并。成功后立即使用新位置，旧目录保留。失败时继续使用原位置，不删除已有资料。

自定义路径保存在本机 UserDefaults；磁盘不可用或路径失效时显示错误，不静默改用其他目录。Mock 使用独立临时目录，不提供真实数据目录切换。

## 故障处理与后续迁移

遇到故障先保留数据目录副本，检查磁盘空间、权限和自定义磁盘是否可用。正常打开后，可通过应用导入 JSON 备份；如需恢复到空库，应先保留原目录，再在设置中选择新的空目录。应用不会自动重置损坏库。

结构变化需追加数据库迁移，并按变化分别评估文档与备份版本，不能机械地同步递增所有版本。新增版本必须验证旧数据升级、失败回滚、备份往返与未来版本拒绝。GRDB 升级单独进行，不能顺手改变已锁定版本。
